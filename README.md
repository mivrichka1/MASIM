# Gene Atlas

Gene Atlas — веб-приложение для проверки фенотипических аннотаций генов человека. Оно получает записи из Ensembl и сопоставляет содержащиеся в них идентификаторы с терминами Human Phenotype Ontology (HPO) через EBI Ontology Lookup Service (OLS). Результаты показываются в таблице и сохраняются в CSV.

[Открыть Gene Atlas](https://gene-atlas.official-healthy-yum.chatgpt.site/)

## Как взаимодействуют агенты

| Агент | Решение модели | Что передаёт дальше |
| --- | --- | --- |
| Ensembl | Выбирает поиск гена по символу, синониму или Ensembl ID. | Запись гена и его фенотипические аннотации агенту HPO. |
| HPO | Для записей без HPO ID выбирает, стоит ли искать по названию и какую фразу использовать. | Термины, определения и результаты проверки идентификаторов агенту проверки. |
| Агент проверки | Готовит справку о функции продукта гена и предлагает варианты для спорных строк. | Карточку гена и рекомендации в таблицу. Статусы по ID рассчитываются кодом. |

Каждая роль использует модель `inclusionai/ling-3.0-flash` через Router AI со своим промптом. Координатор управляет порядком работы. В блоке «Как работали агенты» отображаются запросы к модели, передачи данных и результаты обращений к источникам. Если модель недоступна, система использует правила и отмечает это в журнале.

Например, для `CFTR` агент Ensembl получает запись гена и связанные аннотации. Агент HPO параллельно проверяет уникальные идентификаторы из этих аннотаций через OLS. Агент проверки подготавливает справку и передаёт результат в таблицу. Пользователь может раскрыть найденные термины, вручную выбрать кандидат для спорной строки и выгрузить CSV.

## Источники и инструменты

- [Ensembl REST API](https://rest.ensembl.org/) — поиск гена по символу или ID и получение фенотипических аннотаций через `/phenotype/gene/homo_sapiens/{gene}`.
- [HPO в EBI OLS](https://www.ebi.ac.uk/ols4/ontologies/hp) — получение названий и определений HPO-терминов по ID и поиск кандидатов по названию.

Данные из источников используются как контекст для справки и выбора кандидатов. Статус «Совпадение по ID» определяется программно по ответам API. Справочное объяснение функции гена генерирует модель на основании названия гена и его краткого описания в Ensembl. Его следует сверять с источниками.

В репозитории также есть отдельный экспериментальный Python-модуль `mcp_server/` с JSON-RPC инструментами Ensembl и HPO. Основной веб-интерфейс работает через Worker и обращается к API напрямую.

## Сборка и запуск

Нужны Node.js 22+, доступ к внешним API и ключ Router AI. Устанавливать npm-зависимости не требуется.

```bash
export ROUTERAI_API_KEY='<ключ Router AI>'
npm run build
npm start
```

Локальный сайт доступен на [http://127.0.0.1:8767/](http://127.0.0.1:8767/). `npm start` также выполняет сборку.

## Демонстрация работы

1. Нажмите **CFTR** или **FBN1** и запустите проверку.
2. Посмотрите карточку гена и таблицу аннотаций. Если у записи несколько HPO ID, дополнительные термины раскрываются в строке.
3. В разделе «Как работали агенты» раскройте сообщения Ensembl → HPO и HPO → Проверка.
4. Если доступна строка «Нужен выбор», сравните кандидатов и подтвердите термин вручную.
5. Скачайте CSV с результатами и ссылками.

Совпадение по ID означает, что идентификатор из аннотации Ensembl найден в HPO. Оно само по себе не доказывает причинную связь и не является диагнозом.

## Текущая реализация

Веб-приложение использует JavaScript Worker и модель `inclusionai/ling-3.0-flash` через `https://routerai.ru/api/v1`. Исходный ключ задаётся переменной `ROUTERAI_API_KEY`.

`audit.mjs` содержит агентные роли и обработку аннотаций, `profile.html` — интерфейс, `worker.mjs` — HTTP-маршруты и клиент модели. `build.mjs` собирает Worker в `dist/server/`, `preview.mjs` запускает его локально. Старые Python-модули и чат являются отдельным прототипом.

Результат зависит от доступности источников и качества ответа модели. Записи OLS, которые не удалось получить, отмечаются в таблице.
